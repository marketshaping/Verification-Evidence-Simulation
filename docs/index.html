Why developers pick the amount they do

Largest developerSmallest developer

Expected gain per unit of a developer's own compute: permit money saved minus the expected fine. Each developer hides the amount at the top of its curve. With noisy measurement the curve peaks above zero, so small amounts of hiding always pay.

How the model works

  1. A developer with true compute s declares (1 − Δ)·s. Hiding the share Δ saves p·Δ·s in permits.
  2. With probability ρ it is audited. The audit catches it with probability d(Δ), and the fine is a·Δ·s, up to the cap if there is one.
  3. A measuring check reads compute with noise σ. The alarm threshold is set so honest developers are flagged with probability f, so small under-reports hide inside the noise:
    d(Δ) = d · Φ((Δ − k·σ) / σ), k = Φ⁻¹(1 − f)
  4. A pass-or-fail check (a hidden site is found or not) has d(Δ) = d for any hiding at all, so developers hide either nothing or the maximum.
  5. Each developer picks the Δ with the highest expected gain, and picks honesty when it's a tie. Large-scale hiding stops once ρ·d·a ≥ p.
  6. Developer sizes follow a fixed lognormal spread and always add up to the same total compute.

Extends the two-margin model in Christoph, Risk-Weighted Compute Permit Markets under Imperfect Monitoring (SSRN 6361077). The page calculates the same model as the project's Python code, using central values in place of the random draws.
